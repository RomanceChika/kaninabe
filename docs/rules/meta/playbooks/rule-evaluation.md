# ルール文書の評価

書き上がったルール文書を、**独立した目で**評価するためのチェックリストである。ビルダー×レビュアー体制のレビュアー側が使う。

6 つの観点を順に見る。並びは重要度の順で、**上位原則との整合が最も重い**。テンプレートの節が揃っているかより、書いてある内容が原則と矛盾していないかのほうが、後から直す代償が大きいためである。

各観点には**不合格の条件**を明示してある。「良いと思う」ではなく、条件に当たったかどうかで判定する(判定可能な形にしておくことが、評価が評価として機能する条件である)。

## 目的

- **ルールが上位原則に矛盾していないことを保証する**
- **doc_type の境界の逸脱を検出する**
- テンプレート・フロントマター・参照の整合を確認する

## 前提条件

- 評価の対象が作成または更新済みであること
- 変更内容の概要(新規か更新か、何を変えたか)が把握されていること

**評価者は、書いた本人とは別であることが望ましい。** 書いた側は自分の意図で本文の空白を補って読むので、書いてあることと書いたつもりのことを区別できない。

## 参照するもの

**[../standards/](../standards/README.md) 配下の全ファイルを読んでから評価を始める。** 6 観点のうち 4 つはそこに正がある。サブエージェントに評価を任せる場合は、**オーケストレーターが読むべき文書のパスをプロンプトに明示する**(サブエージェントは CLAUDE.md を読まない)。

## 手順（概要）

### 手順1: 上位原則との整合性チェック（最重要）

1. 対象の `norms` を確認する
2. `norms` の各 ID の文書を読み、矛盾がないかを確認する
3. **principles 配下の全 PRIN** を読み、矛盾がないかを確認する
4. 層に応じた上位レイヤーを確認する

| 対象の doc_type | 確認する上位 |
|---|---|
| `architecture` | 全 PRIN |
| `process` | 全 PRIN + 関連する architecture |
| `decision` | 全 PRIN + 関連する architecture |

**不合格の条件**

- 上位の原則に矛盾する内容がある
- `norms` に記載すべき上位文書が記載されていない
- `norms` に記載された ID が存在しない

### 手順2: 概念の一貫性チェック

既存の文書と概念・用語が矛盾していないことを見る。同じディレクトリの他の文書を確認し、用語の使い方が既存と一致するか、同じ概念に別の定義や解釈が生まれていないかを確かめる。

**不合格の条件**

- 既存と矛盾する概念定義がある
- 用語が統一されていない(同じものを別の名前で呼んでいる)
- 既存のルールと重複している

3 つ目が単一情報源(PRIN-0007)への違反である。**同じことが 2 か所に書かれていたら、どちらかを参照に落とす。**

### 手順3: doc_type 境界の遵守チェック

[doc_types.md](../standards/doc_types.md) を読み、内容がその doc_type の「書くこと」に合致しているか、「書いてはいけないこと」に違反していないかを見る。

**不合格の条件**

- 「書いてはいけないこと」に該当する内容がある
- 内容が doc_type の責務を逸脱している

### 手順4: テンプレート準拠チェック

解決されるテンプレートを確認し、必須の節(H2)が全て存在するかを見る。

**テンプレートが `h2_policy: open` を宣言している場合(現状 directory_guide)は、テンプレートに無い節を咎めない。** 案内すべき中身がディレクトリごとに違うためである。判断の基準は [template_policy.md](../standards/template_policy.md)。

**不合格の条件**

- 必須の節が欠けている
- closed なテンプレートの配下で、正当な理由なく節が追加されている

### 手順5: 参照整合性チェック

```bash
npm run verify
```

**不合格の条件**

- 検証がエラーで終わる
- 存在しない ID への参照がある(M3)
- 循環参照がある(M6)

### 手順6: フロントマターの正確性チェック

[frontmatter_policy.md](../standards/frontmatter_policy.md) と [id_policy.md](../standards/id_policy.md) を確認する。

**不合格の条件**

- 必須フィールドが欠けている
- ID が命名規則に違反している
- ID が重複している
