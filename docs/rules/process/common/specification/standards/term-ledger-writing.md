# 用語の台帳(term_ledger)の書き方

`docs/specs/terms.md` に置く `term_ledger`(用語の台帳)の YAML スキーマと、検証器が実行するチェック(M7〜M9 / M11)と、同じ置き場で人が書く文の語の接地を見る M10・文体を見る M12 を定義する。

## 目的

- **1 つの概念に 1 つの綴りを持たせる。** 規約・ブック・設計メモの説明語(造語と借用語)は、これまで綴りの規則が無かった。1 概念に 3 つの綴りができると grep が効かず、AI への指示がぶれ、レビューで「これは前に読んだあれと同じか」が毎回起きる。
- **台帳の仕事は別名を許すことではなく、禁じること。** 語を 1 行で宣言し、使わない綴り(`avoid`)を機械に見張らせる。
- **自然な日本語があればそれを使い、無ければ無理に訳さず英語のまま書く。** 英語のままの語は等幅で書き、初出の文書に 1 行の説明を置く(ユーザー原則。review-queue §21)。
- **語を選ぶ順は、一般の概念の名前 → 英語のまま → 造語と比喩は使わない。** 既に世の中にある概念の名前(日本語でもカタカナでも、普通に通じるもの)があれば、それを使う。無ければ英語のまま等幅で書き、1 行の説明を置く。造語と比喩は、読み手に意味の補完を求めるので作らない。**言い直しの案を出す前に、その案が比喩でないかを確かめる**(ユーザー決定 2026-09-30。例: 『机上』『紙の上』『レンズ』『顔』『降りる』は比喩なので、『シミュレーション』『検討』『見方』『見分けのつかない形』『反映される』に言い直した。『名乗る』も擬人化の比喩なので、『宣言する』『報告する』『渡す』『指定する』『返す』などに言い直した。『走行』『網の穴』『壊し込み』も比喩の造語なので、『実行』『検査の漏れ』『わざと壊す確認』に言い直し、『許可証』は英語のまま `permit` と書く。『窓』『展開表』『一生』『閉じた語彙』『倒れ方』『横道』『D 付箋』『3 分ブロック』『立ち止まる場所』『人が読む面』も、『スコープ条件』『マトリクス』『ライフサイクル』『値域』『鍵が無いときの挙動』『補足枠』『保留の仮定』『冒頭の要約』『判断ポイント』『人向けの表示』に言い直した。検査や処理が失敗する意味の『倒す』『倒れる』も比喩なので、『失敗する』『エラーにする』『落ちる』に言い直した(『安全側に倒す』『既定値に倒す』のように決まった側へ寄せる一般の慣用は残す)。『置き場』『写し』『場面』『段』『手』『印』『表示モード』『執行点』は、一般語か仕様の語の訳であって造語ではないので残し、台帳の `origin` を直した。一般語の複合で意味が復元できる『見張りテスト』『検査の漏れ』『通し実行』『文言の層』は、造語の例外として `not` に理由を書いた)。
- **業務の語とは別物にする。** 業務の語(会議・司書など)は `docs/knowledge/TERM-*.md`(W 層)が持つ。この台帳が持つのは**仕組みの側の説明語だけ**で、語釈は 1 行である。

配置の話(なぜ仕様の木の直下か)をここに書き写さない。台帳は 1 プロジェクト 1 ファイルで、`id` は `term-ledger` 固定である。

## ルール・基準

### 1 行が宣言すること

`terms` は次の 8 つのキーを持つ行のリストである。**未知のキーは書けない**(M11)。

| キー | 必須 | 中身 |
|---|---|---|
| `term` | ○ | 本文で使う綴り(日本語、または英語のまま)。台帳の中で一意 |
| `id` | ○ | 英語の識別子(スネークケース。コード・仕様の綴り)。台帳の中で一意 |
| `gloss` | ○ | 1 文の定義(語の意味だけ)。ブックの表とツールチップに出る |
| `origin` | ○ | `borrowed`(借用)/ `coined`(造語)/ `literal`(直訳)/ `english`(英語のまま) |
| `first` | ○ | 初出 — この語を導入している文書の、リポジトリルートからの相対パス |
| `face` | ○ | `framework`(仕組みの説明語)/ `book`(ブックの生成文が読者に出す語) |
| `avoid` | — | **使わない綴り**の一覧。別名を許す欄ではなく、禁じる欄である(機械が見張る。M9) |
| `not` | — | **この語を使わない用法**(1 行)。綴りでは言えない線引き —— 多義になった語を 1 つの意味に限るときの、ほかの意味の扱い(人が読む) |

- **すべきこと:** 新しい造語を文書に書く前に、台帳に 1 行載せる。`gloss` は 1 文(文体は設計メモ §7-6 に従い、括弧の補足を避ける)で、**語の意味だけ**を言う。2 文目に入る情報は、この語を使わない用法なら `not` に 1 行で、補足なら `first` の文書の説明に移す(2 つの情報が要るなら「〜で、〜」と 1 文にする。句点で区切られた文が 2 つ以上あると M11 が落とす)。`first` は、語を実際に導入している文書を指す。
- **すべきこと:** 英語に戻した語(`origin: english`)は、`avoid` に旧い日本語の綴りを載せる。**ただし一般語そのもの(世界・面など)を `avoid` に載せない** —— 一般語は別の意味でも正しく使われるので、旧綴りだけを指す複合語で書く(例: `世界の設計図`・`外から届く面`)。
- **すべきこと:** 英語に戻した語は、**台帳の `gloss` が言う 1 つの意味だけ**に使う。ほかの意味(一般語の用法・別の道具・別の概念)には元の日本語を使うか、別の語を台帳に足し、**線引きを `not` に書く**(例: `walker` の `not` は「`samples:db` などの通し実行はこの語で呼ばない」)。同じ綴りが 2 つの意味を持つと、1 概念 1 語が崩れる。
- **すべきこと:** **一般語の一部になる綴りは `avoid` に載せない。** 旧綴りそのものが別の正しい語の中にも出るなら、その綴りを載せると正しい用法を責める(例: `行列` は `待ち行列` にも出るので、マトリクスの `avoid` には `マス目` だけを載せ、`行列` は `not` に書く)。載せたい旧綴りが一般語と同じなら、旧綴りだけを指す複合語にする(例: `顔` は `顔ぶれ` にも出るので `同じ顔で` のような言い回しだけを、`降り` は `降りて` などの活用を別々に載せ、一般の動詞と同じ綴りで誤って当たる形は JSDoc の実測で人に知らせる。`紙の上` は本物の紙の話にも出るので `紙の上で` は載せず、`紙の上の` だけを載せる)。活用する旧綴り(`降りる` 系)は例外で、捕る形・取りこぼす形・誤って捕る形は `prose.ts` の JSDoc に実測で書く。
- **すべきこと:** 英語のまま使う語(`origin: english`)は、`first` の文書の**初出の行か直後の行**に、語の意味を 1 行で書き、行末に印 `<!-- term: {id} -->` を付ける。説明と印は**同じ行**に置く(M7 が見る)。
- **してはいけないこと:** `avoid` に、自分の `term` や別の語の `term` を書く。台帳が自分で矛盾する(M11 が落とす)。
- **してはいけないこと:** `gloss` に仕様 ID・ファイルパスを書く(読者はそれを持たない)。

### `face: book` の行は表紙の表になる

`face: book` の行は、ハンドブックの表紙(`docs/book/index.html`)の「この本に出てくる言葉」の表として**宣言順に生成される**(生成器は表の行を手書きで持たない)。

- `gloss` の中の `{例}` は、その語の例を**仕様の宣言から採って差し込む位置**である(対応する語は `state_machine` と `role`。宣言が無ければ空になる)。例に出す語は仕様から採るので、どのシステムでも同じ説明文の中にそのシステムに無い概念の名前が混ざらない。
- 台帳が無い製品・`face: book` の行が無い製品では、表を作らず、その旨を 1 行で言う。

### 検査

| 検査 | 見るもの | 重さ |
|---|---|---|
| **M11** | 台帳のスキーマ適合(必須キー・値域・id と term の一意・`first` が相対パス・`gloss` が 1 文・`avoid` が台帳の語を禁じていない・`not` が空でも複数行でもない)。`M0`(`docs/run.ts` の走査範囲の検査)とは別の検査である | error |
| **M7** | 各行の `first`(初出)が実在し、その文書に `term` の綴りが書かれていること。**`origin: english` の語は、初出の行か直後の行に印つきの 1 行説明(`<!-- term: {id} -->`。説明と同じ行・行に語の綴りを含む)があること** | error |
| **M8** | 台帳の語が、走査範囲のどの本文・コメントにも出てこない(死んだ行) | warning |
| **M9** | 台帳が `avoid` に挙げた綴りが、走査範囲の本文・コメントに出ている | warning(ファイル 1 件につき 1 件) |
| **M10** | 人が書く文(`summary:`。M12 と同じ集め方)の**語の接地**。次の 4 つのどれか。**仕様に無い語**(2 字以上の漢字・カタカナの連なりが、ドメイン仕様の frontmatter の値(`summary` 自身を除く)にも台帳の語にも無い。連なりは 2 字以上の仕様の語に割れれば通る。送り仮名で割れた語は 1 字の連なりになるので見えない)/ **数字**(件数・欄数・本数は生成が入れる)/ **識別子**(台帳の語でない英字の語)/ **等幅**(`` `…` `` で書いた語)。文体は見ない(M12 の仕事)。summary 1 つにつき 1 件。**試験運用**(見える範囲だけの検査で、仕様の外の語がすべて拾えるわけではない) | warning |
| **M12** | 人が書く文(仕様の frontmatter の `summary:`。場所は決め打たず、木の中の `summary` の鍵を全部拾う)の文体。**1 文が 50 字を超える・括弧の補足・文中の記号接続(`=` `→` `/` `・`)・常体(だ・である・のだ。**辞書形**の言い切り「締める。」「ある。」も常体。敬体で終わる文と体言止めは常体ではない)**のどれか(設計メモ §7-6)。等幅(`` `…` ``)の中は数えない。summary 1 つにつき 1 件 | warning |

- **走査範囲は 4 種類で、範囲外は理由つきで宣言する**(`lib/terms/scope.ts`。範囲が狭いと「M9 が 0 件」が「旧綴りが無い」を意味しない)。**仕組みが綴りを持つのは、配布物にもある置き場(規約・スキル・ブック・仕様・実装の木)だけ**である。設計メモ・引き継ぎ文書・案内・フック・CI・歴史の記録のような**製品ごとの置き場は、製品が `product.md` の `term_scan` で宣言する**(`prose_trees` = 本文の全行を読む木 / `prose_files` = 読む Markdown のファイル / `script_trees` = `#` コメントを読む木 / `history` = 読まない歴史の記録。末尾が `/` の項目は木ごと外す印)。宣言の無い製品は、その分を読まない。値の検査は P0(絶対パス・`..`・空・知らない欄を拒む)。以下の置き場の名前は、このリポジトリの宣言の中身である。
  - **Markdown の本文(全行)** … `docs/rules` / ブック(`roots.book`)/ スキル(`.claude/skills/**`)と、宣言の `term_scan.prose_trees`(このリポジトリでは `docs/design` / `docs/handoff`。`history` の項目は除く)
  - **Markdown の本文(生成ブロックを除く)** … 仕様の木(`roots.specs`。YAML frontmatter の値と `AUTO-GENERATED:` の生成ブロックは読まない)と、宣言の `term_scan.prose_files`(このリポジトリでは `CLAUDE.md`)
  - **コードのコメントと、日本語を含む文字列リテラル** … `legacy/spec-tools/**` / `framework/**` / アプリの実装の木(`roots.app`)の `.ts` `.tsx` `.mts` `.mjs` ほか。コメントの取り出しは W2 と**同じ走査器**(`generality/prose-scan.ts`)。**文字列リテラルは、ひらがな・カタカナ・漢字を 1 文字でも含むものだけ**を読む(人に見えるメッセージ・テストの題。識別子・パス・英語のラベルは文ではない)。テストのファイルは `describe` / `it` / `test` の**題だけ**を読む(入力と期待値は、旧い綴りを検査するために旧い綴りを渡すので読まない)
  - **シェルと YAML の `#` コメント** … 宣言の `term_scan.script_trees`(このリポジトリでは `.githooks` と `.github`。`lib/terms/hash-comments.ts`)。`#` がコメントになるのは、行頭か空白の直後で、引用符の外・ヒアドキュメントの本文の外にあるとき。`"a # b"`・`$#`・`foo#bar` のような文字列や特殊変数は切らない
  - **読まない(宣言)** … 生成物(先頭に生成の目印を持つコードと、仕様の生成ブロック。綴りの正は生成器と仕様にあり、`generate:check` が鮮度を見る)/ 適用済みの migration と supabase の設定(1 バイトも動かさない。C23)/ 歴史の記録(宣言の `term_scan.history`。このリポジトリでは `NOTES.md` / `BACKLOG.md` / `docs/handoff/` の `review-queue.md`・`session-handoff.md`・`roadmap.md` と外部との連絡口の木。当時の言葉のまま残す。**名指しで数える** —— `docs/handoff/` の木ごとは外さない。`runbook.md` などは生きた読み物。**台帳だけのコミットは pre-commit が中身の検査を飛ばすが、この範囲に入る `docs/handoff/` の文書が混ざれば verify だけ回す**)/ migration の SQL に出る文言を持つ生成器の文字列リテラル(`messages-api.ts`・`messages-ddl.ts`。変えると次の generate が適用済みの migration と食い違う)/ テストの文字列リテラルのうち題以外 / 日本語を含まない文字列リテラル / 仕様の frontmatter の値と台帳の欄(宣言であって散文ではない)
- **引用は置換しない。** 人の発言(例: ADR の「ユーザーの方針」)と検査の出力の写しは、旧い綴りでも原文のまま残す記録である。**M9 は引用ブロック(`> ` で始まる行)と、かぎ括弧「」の中を読まない**(同じ行で閉じていない「は引用として扱わない)。引用の外の同じ行の綴りは数える。引用を書き換えると記録が変わるので、旧い綴りを直したくなっても直さない。
- **M9 の照合は語の境界を見る。** 前後の隣の文字が、綴りの端の文字と同じ種類(漢字・カタカナ・ひらがな・英数字)なら語の途中として数えない。例: `世界` を禁じても `閉世界` は旧綴りの使用ではない。**漢字を含みひらがなで終わる綴り(活用する語)は、後ろに続くひらがなを語の途中にしない**(送り仮名の後ろは助詞か活用語尾だからである。例: `降りる` は `降りるのは` でも数える)。取りこぼす形(漢字が続く複合語。例: `半固定物`)があるのは、誤検出の側に倒さないためである。**英字の綴り(例: `parity`)は、`-` `.` `/` でもう 1 つの英数字の連なりにつながるなら識別子の一部**(`data-table-parity` / `lib/parity/x.ts`)として数えず、**大文字小文字は区別しない**(例: `Parity` / `PARITY` も数える。`expectDdlParity` のような CamelCase は英字が隣にあるので識別子)。日本語の綴りには識別子の規則を当てない(`ステップ/手順` のような列挙を見逃さないため)。捕る形・捕らない形・誤って捕る形の実測は `findSpelling` の JSDoc に書く。
- **消し込みの道は 2 つで、免除の一覧は持たない**(PRIN-0006)。①本文を台帳の語に書き換える。②旧い綴りを**説明するために**挙げている行には、行のどこかに `例:` を書く(印のある行は走査から外れる)。`avoid` が広すぎて誤検出が出るなら、台帳の側を直す。
- 執行者は `npm run verify`(M 群の続き。`lib/terms/**`)。

### 語を足す・綴りを改めるとき

1. 新しい造語を書くなら、先に台帳に載せる(`first` は書く文書のパス)。
2. 綴りを改めるなら、`term` を新しい綴りにし、旧い綴りを `avoid` に載せる。M9 が残った旧綴りを名指すので、それを消し込む。
3. `face: book` の語を足したら `npm run generate` を回す(表紙の表が変わる)。
