# PRIN-0005 — 境界を尊重する

アーキテクチャが定めた**境界の責務**と**依存の向き**を、実装の側が守ることを要求する原則。

## 原則 {#statement}

- **責務の不可侵**: 各境界(モジュール・コンポーネント・レイヤー)の役割の外へ、責務を漏らさない。
- **依存の向きの遵守**: [architecture](../../architecture/README.md) が定めた依存の向きを逆流させない。
- **役割分担の但し書き**: 境界を「明確にする」「検証可能にする」ことは [PRIN-0003](./PRIN-0003-testability.md) の担当である。本原則が扱うのは、既に引かれた境界を**侵さない**ことだけである。観測を境界でどう扱うかは、各スタック固有の原則に委ねる(該当する原則はまだ起こしていない)。

## 背景 {#rationale}

境界が曖昧になると責務が混ざる。責務が混ざると、変更したときにどこまで影響するのかが読めなくなる。

依存の向きが崩れると、テスト可能性([PRIN-0003](./PRIN-0003-testability.md))と保守性がまとめて損なわれる。内側が外側を知っている構造では、内側だけを取り出して確かめることができない。

アーキテクチャで境界と依存の向きを定義するのは、それを実装側でも同じように守らせるためである。定義しただけで守られない境界は、境界ではなく願望である。

## 影響 {#implications}

- **責務**: 境界の役割に無い処理を、そこに書かない。はみ出した責務は、本来の境界へ移す。
- **依存の向き**: 各スタックの architecture が定めた向きに従う(たとえば内側から外側へ、という定義がある場合はそれに従う)。
- **定義と遵守の分業**: 「何がどの層・どのモジュールに属するか」を**定義する**のは architecture の役割である。本原則の役割は、その定義を**守らせる**ことに限られる。

## 例外 {#exceptions}

- architecture の変更に伴って境界や依存の向きが変わる場合は、[PRIN-0004](./PRIN-0004-record-intent.md) に従い decision に記録する。境界を動かすこと自体は禁じられていないが、黙って動かすことは禁じられている。
