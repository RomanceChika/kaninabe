# PRIN-0007 — 仕様は単一の出典を保つ

同じ事柄を 2 か所に書かず、**出典を 1 つに定めて他は参照にする**原則。[PRIN-0001](./PRIN-0001-spec-as-truth.md) を文書の構造として実装したものである。

## 原則 {#statement}

- 仕様は**無矛盾**であり、**重複した定義を持たず**、**出典が 1 つ**であること。
- 同じ事項を複数の場所に書かない。必要なら参照で接続する。
- 更新するのは**出典の側だけ**である。
- **自己位置づけ**: [PRIN-0001](./PRIN-0001-spec-as-truth.md) が言う「唯一の正」は、それが分散して矛盾した時点で成立しない。本原則は、その「唯一」を文書の構造の上で保つためのものである。

## 背景 {#rationale}

同じことを複数の場所に書くと、いずれ片方だけが更新される。これは注意力の問題ではなく、時間の問題である。

その結果として矛盾が生まれ、どれが正なのかが判定できなくなる。**そのとき PRIN-0001 と [PRIN-0006](./PRIN-0006-evaluability.md) が同時に形骸化する。** 正が分からず、判定もできない状態になる。

出典を 1 か所に置き、他はそこを指すだけにしておけば、更新すべき場所が 1 つに限定される。矛盾の発生源そのものを潰すのが、この原則の狙いである。

## 影響 {#implications}

- **重複の回避**: 同じ定義・振る舞い・制約を二重に書かない。必要なら参照リンクで代替する。
- **出典のみ更新**: 更新の対象は、その事項の出典(唯一の定義が置かれている文書・節)である。参照する側は「これは参照である」ことを明示し、出典の変更に追随する。
- **矛盾の禁止**: 矛盾を見つけたら、出典を 1 つに決めたうえで、他を参照に書き換えるか削除する。「どちらも残す」で終わらせない。
- 「どれを出典とするか」「参照をどう書くか」は、この原則の**適用**として process・specs の規約側に置く。

## 例外 {#exceptions}

- **要約・一覧・ダッシュボードのように、出典を指し示すこと自体が役割の文書**は、重複として扱わない。ただし条件がある。**「これはコピーではなく参照である」ことを明示する**ことである。無条件の免除ではない。レビュー要約、各ディレクトリの README の一覧、生成されたマトリクスはいずれもこの例外に乗っている。
- 移行や統合の途中は、一時的な重複を許容する。完了した時点で出典を 1 つに畳み、他を参照へ揃える。
