# PRIN-0010 — 最小権限と責務分離を守る

権限を必要最小限に絞り、**矛盾しうる責務を同じ主体に持たせない**原則。[PRIN-0009](./PRIN-0009-secure-by-default.md) が初期値の向きを扱うのに対し、こちらは権限の量と分割を扱う。

## 原則 {#statement}

この原則は 2 本立てである。1 つの文書に同居させているのは、**どちらも影響範囲を局所化することが目的**だからである。

- **最小権限**: 付与する権限は、責務の遂行に必要な分だけにする。過剰なアクセス権・実行権・情報アクセスを与えない。
- **責務分離**: 単一の主体(ユーザー・プロセス・コンポーネント・ロール)に、矛盾しうる責務を集約しない。分離の効果は、誤用と濫用の影響をその主体の範囲に閉じ込めることである。

## 背景 {#rationale}

過剰な権限は、漏洩・誤操作・侵害が起きたときの被害範囲をそのまま拡大する。持っている権限の広さが、そのまま事故の広さになる。

責務が一点に集まっていると、その主体が侵害されたときの影響が大きくなる。1 つ抜かれれば全部が抜かれる、という構造になる。

両方を守ると、主体ごとに影響範囲が限定される。副次的な効果として、監査と検証も容易になる。「この主体に何ができるか」が短く言えるからである。

## 影響 {#implications}

- **権限**: ユーザー・ロール・サービス・コンポーネントに与える権限は、責務の遂行に要する最小限にする。**既定値は「なし」であり、必要に応じて足す。** これは [PRIN-0009](./PRIN-0009-secure-by-default.md) の「初期値は安全側」と同じ向きである。
- **責務分離**: 分離すべき対の例は、認可と実行、監査と操作、開発と本番である。**単一の主体を「全権」にしない。**
- 個別の権限モデル・ロール設計・責務の分割は、この原則の**適用**として各スタックの architecture・規約側に置く。

## 例外 {#exceptions}

- 開発・検証用のローカル環境では、利便性のために緩めてよい。ただし、本番・共有環境で両方の原則を満たす旨を規約で明示する。
- **責務分離を厳密に適用すると運用コストが極端に増える場合**は、適用範囲を限定してよい。ただし条件として、**decision にトレードオフを記録する**こと。この逃げ道は、責務分離を教条にしないために用意してあるが、手続きの縛りは外さない。
