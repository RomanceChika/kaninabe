# PRIN-0008 — 仕様と実装の対応は追跡可能に保つ

仕様・実装・テスト・decision の対応を、**ID と参照で辿れる**状態に保つ原則。

## 原則 {#statement}

- 追跡の対象は**仕様 ↔ 実装**の組であり、そこに**テスト**と**decision** が加わる。
- **双方向**で辿れること。仕様からそれが効いている先へ、そして効いている先から仕様へ、どちらの向きにも辿れなければならない。
- 追跡の手段は ID・フロントマター・参照リンクである。**機械的に辿れる形であるほど強い。**
- **自己位置づけ**: [PRIN-0001](./PRIN-0001-spec-as-truth.md) の乖離検出・影響範囲の把握・変更管理は、この追跡可能性を前提にしている。[PRIN-0004](./PRIN-0004-record-intent.md) とセットで、変更時の「意図」と「影響」を一貫して扱う。

## 背景 {#rationale}

対応が辿れなければ、乖離の検出も影響範囲の把握もできない。仕様を 1 行変えたときに、直すべき実装とテストがどれなのかを特定できない。

その状態では PRIN-0001 の運用が破綻する。「仕様が正」と言えても、その正がどこに効いているのかが分からないからである。

ID と参照を一貫して使えば、人間と AI の双方が対応関係を**機械的に**辿れる。人間が読んで辿れるだけでは足りない。逆引きを人手の全文検索に頼っている限り、影響範囲は毎回「たぶんこれで全部」になる。

## 影響 {#implications}

- **仕様 → 実装・テスト・decision**: 仕様の側から、対応する実装(コード・ファイル)、テスト、関連する decision への参照を持つ。手段はフロントマターの `decisions` と本文のリンクである。
- **実装・テスト・decision → 仕様**: 逆向きも持つ。手段はコメント・フロントマター・README への仕様 ID とリンクの記載である。
- **ID の一貫利用**: `PRIN-xxxx` / `ARCH-xxxx` / `ADR-xxxx` と、仕様の中の識別子を一貫して使い、参照で接続する。準拠先は [id_policy](../../meta/standards/id_policy.md) と [reference_policy](../../meta/standards/reference_policy.md) である。
- 参照をどの粒度で書くか、どのツールを使うかといった個別の追跡ルールは、この原則の**適用**として process・規約側に置く。

## 例外 {#exceptions}

- 既存資産の移行中は、未整備の部分が残ることを許容する。新規・変更した箇所から順に付与し、移行が終わった時点で揃える。
- 調査・PoC のコードは、本番・共有対象へ昇格させる時点で追跡を付与する。
