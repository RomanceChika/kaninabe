# architecture/system/common — リポジトリ全体の構成

この階層が担当するのは、**スコープに閉じないコードレベルのアーキテクチャ**である。具体的にはリポジトリ全体の構成と、実行基盤の役割分担がここに入る。

`backend` にも `frontend` にも寄せられない「どこで何が動くか」を 1 か所に集める場所である。

---

## 配下の文書

| ID | 文書 | 内容 |
|---|---|---|
| ARCH-0001 | [ARCH-0001-compute-placement.md](./ARCH-0001-compute-placement.md) | 計算基盤の配置ポリシー。処理の種類から実行場所が一意に決まる配置決定表、Vercel・Cloudflare・Supabase の責務分担、既定を外れる場合の昇格条件、ホスティング制約への対処 |

`ARCH-xxxx` を足したらこの表に行を足す。

### 落としてはいけない考え方

- **処理の種類から実行場所が一意に決まる。** 配置は設計者の好みで決めるものではなく、決定表を引くものである。決定性が無いと、同じ種類の処理が人によって別の基盤に散る。
- **既定を外れるには昇格条件を満たす。** 「昇格条件」(既定を外れるために満たすべき明示条件)はこのリポジトリ全体で使う語彙であり、ARCH-BE-0015 や ADR-0007 にも同じ形で現れる。
