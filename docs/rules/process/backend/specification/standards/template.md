# {タイトル}

この基準が何を定めるものかを 1 行で書く(仕様書の書き方・基準・テンプレートに関するものであること)。

## 目的

- このプロセスで何を達成するかを書く。
- architecture/specification と連携する場合はその旨を書く。

## 参照するもの

- [ARCH-SP-BE-0001](../../../../architecture/specification/backend/ARCH-SP-BE-0001-backend-spec-structure.md) — 仕様書の配置・構成。**必ず挙げる。**
- その他、正とする文書を続けて並べる。

ARCH-SP-BE-0001 を毎回挙げるのは、**配置の正が 30 側にあることを書き手に思い出させるため**である。ここで配置を書き直しそうになったら、それは 30 に足すべき変更である。

## ルール・基準

**すべきこと**と**してはいけないこと**の 2 ラベルで、断定形で書く。

- **すべきこと**: {守るべき形}。理由も添える。
- **してはいけないこと**: {禁じる形}。例えば `layers`(層ごとの実装のきまり)は実装の話なので specification 側には置かない。
